## 1. PROJECT OVERVIEW

**QuickNotes** is an AI-powered study-assistant SaaS. A signed-in user pastes
text (or uploads documents), picks an output format, and the app streams back
formatted, exam-ready study notes that can be copied or exported to PDF/DOC.

- **What it does:**
  - **Chat / note generation** (`/chat`): paste content → choose a format (Key
    Points, Main Concepts, Exam Points, Short Notes, Speech Notes, Presentation
    Notes, Summary, MCQs, Quick Test) → streamed Markdown answer.
  - **Document upload** (`/api/upload`): PDF / DOCX / PPTX / TXT → text
    extraction → stored per-collection → AI study notes generated by polling.
  - **Quick Test**: generates an interactive multiple-choice quiz (JSON) from
    pasted content, graded client-side.
  - **Export**: server returns a printable HTML document ("Save as PDF"), with a
    client-side jsPDF fallback and a DOC/text fallback.
  - **Feedback**: in-app feedback form persisted to Supabase.
- **Target users:** students, educators, researchers converting dense material
  into concise notes.
- **Current stage:** working single-developer production app deployed at
  `https://quicknotess.space`. Several subsystems are partially wired or broken
  — see **Section 12**.
- **Target scale:** small (designed around per-user rate limits of ~10–15
  req/min and single-instance Vercel serverless functions). Not architected for
  high concurrency today.

### `match_documents()` RPC — shipped at vector(384), NOT yet deployed
As of 2026-06-01 the chat route **no longer calls** this RPC at runtime: RAG is
short-circuited behind `RAG_ENABLED=false` (see §7). A correctly-dimensioned
definition now lives at [supabase/migrations/match_documents.sql](../supabase/migrations/match_documents.sql)
at **vector(384)** (matching `document_chunks.embedding` and the embeddings the
code produces). It must still be **deployed to Supabase**, and `document_chunks`
must be populated, before `RAG_ENABLED` is flipped to true.

The shipped definition (also reproduced here for reference):

```sql
-- Recommended (NOT yet in repo). Set VECTOR(n) to match your stored embeddings.
create or replace function match_documents(
  query_embedding vector(384),     -- or 1536 if using OpenAI text-embedding-3-small
  match_threshold float,
  match_count int,
  user_id uuid
)
returns table (id uuid, content text, similarity float)
language sql stable
as $$
  select dc.id,
         dc.content,
         1 - (dc.embedding <=> query_embedding) as similarity
  from document_chunks dc
  where dc.user_id = match_documents.user_id
    and dc.embedding is not null
    and 1 - (dc.embedding <=> query_embedding) > match_threshold
  order by dc.embedding <=> query_embedding
  limit match_count;
$$;
```
> Note: the route also reads `documents(name)` off the returned rows for source
> labels, so a production RPC should return enough to join document names.

## 7. API ROUTES REFERENCE

All routes are App-Router handlers under `app/api/`. "Auth" = `requireAuth()`
unless noted. Error responses use `ErrorHandler.handle` → `{ success:false,
message, error:{code} }` unless the route hand-rolls its own JSON.

### `POST /api/chat`  — [route.ts](../app/api/chat/route.ts)
- **Purpose:** main streaming chat / note generation with RAG + persistence.
- **Auth:** required (bearer or cookie). **Runtime:** nodejs, **maxDuration:** 120s.
- **Rate limit:** middleware 10/min + `globalRateLimit` 15/min + per-user
  in-flight lock `chat` (130s TTL).
- **Request body (JSON):** `{ question: string (≤50,000 chars), prompt?: string,
  conversationId?: string, title?: string }`. Body size capped at 1 MB via
  `content-length`.
- **Response:** `text/event-stream` (SSE). Events: `data: {"content":"..."}`,
  final `data: {"conversationId","sources"}`, then `data: [DONE]`; errors as
  `data: {"error":"..."}`.
- **Key logic:** dedups the user message; creates a conversation if none; **RAG is
  gated behind `RAG_ENABLED=false`** so no embedding/RPC runs (answers without
  document context); builds a prompt (uses caller `prompt` if provided, else a
  default); streams via `AiService.streamChat`; a `TransformStream` accumulates the
  assistant text and saves it on flush.
- **Known issues:** RAG disabled until `document_chunks` is populated + the RPC is
  deployed (§5/§9/§12); some comments still reference Cloudflare/DeepSeek.

### `GET /api/chat/history`  — [history/route.ts](../app/api/chat/history/route.ts)
- **Purpose:** list a user's conversations for the sidebar.
- **Auth:** required. **maxDuration:** 15s.
- **Rate limit:** Upstash sliding window 60/min keyed by client IP.
- **Query:** `?limit=` (1–50, default 10).
- **Response:** `{ conversations:[{id,title,created_at,updated_at}], meta:{...} }`.
- **Key logic:** Redis cache (`chat-history:{userId}:{limit}`, 60s TTL); 3s DB
  timeout (returns `[]` on missing-table `42P01`); ETag header.
- **Known issue:** the chat UI now queries Supabase directly in
  `loadChatHistory()` and **does not call this route** — it is effectively
  unused by the frontend (kept for API consumers).

### `GET /api/chat/load`  — [load/route.ts](../app/api/chat/load/route.ts)
- **Purpose:** load one conversation + all its messages.
- **Auth:** required. **Query:** `?id=<conversationId>` (required).
- **Response:** `{ conversation:{id,title,created_at}, messages:[...] }`.

### `POST /api/chat/save`  — [save/route.ts](../app/api/chat/save/route.ts)

- **Purpose:** accept files, extract text, store per-collection for later AI
  summarization.
- **Auth:** required. **Runtime:** nodejs, **maxDuration:** 60s. Per-user

### `GET /api/notes/generate`  — [notes/generate/route.ts](../app/api/notes/generate/route.ts)
- **Purpose:** polled background worker that AI-summarizes uploaded documents and

- **Auth:** required. **Runtime:** nodejs, **maxDuration:** 60s. Per-user
  in-flight lock `notes-gen:{collectionId}` (70s TTL). Uses **service role**.
- **Query:** `?collectionId=` (required). Polled by the client every ~3s.

## 8. AI SYSTEM

Source: [aiService.ts](../app/lib/ai/aiService.ts),
[geminiGateway.ts](../app/lib/ai/geminiGateway.ts),
[openrouterGateway.ts](../app/lib/ai/openrouterGateway.ts),
[config.ts](../app/lib/config.ts).

- **Provider / gateway:** **Direct calls to OpenRouter** (no Cloudflare/Portkey).
  `AiService.useGemini(model)` returns true only for `gemini*`/`google/gemini*`
  models with a Google key present → `GeminiGateway`; everything else (current
  config) → `OpenRouterGateway`. Gemini is disabled (see §2).
- **Primary model:** `deepseek/deepseek-chat` (`AI_MODEL`) via OpenRouter. Config
  default if unset: `deepseek/deepseek-r1`. Requires `OPENROUTER_API_KEY`.
- **Fallback model:** `meta-llama/llama-3.3-70b-instruct` (`FALLBACK_MODEL`),
  only reachable via `OpenRouterGateway` (key commented out → cross-provider
  fallback still cannot run). **As of 2026-06-01 the Gemini path has retry** (see
  below); it has no cross-provider fallback or circuit breaker.
- **Streaming:**
  - Gemini: `POST {BASE}/models/{model}:streamGenerateContent?alt=sse`; tokens at
    `candidates[0].content.parts[0].text`. 90s timeout (`AbortSignal.timeout`).
  - OpenRouter: `POST /chat/completions` with `stream:true`; tokens at
    `choices[0].delta.content`. 90s stream timeout / 35s non-stream.
  - `AiService.streamChat` normalizes both into the app SSE format
    `data: {"content":"..."}` and appends `data: [DONE]`.
- **Retries / resilience:**
  - **OpenRouter:** exponential backoff with jitter on 429/5xx, `RETRY_ATTEMPTS=2`;
    circuit breaker opens for 30s after 5 consecutive failures (per Lambda instance).
  - **Gemini (added 2026-06-01):** `withGeminiRetry` wraps both `streamChat` and
    `complete` — retries **429/500/502/503** with exponential backoff + jitter
    (500ms→1000ms), **max 2** retries; **never** retries 400/401/403. Status is
    parsed precisely from the `Gemini <status>` error prefix.
- **Non-streaming completion:** `AiService.complete` (used by upload/notes) with a
  study-guide system prompt; returns plain text.
- **Embedding model + dimensions:** OpenAI `text-embedding-3-small`, requested with
  **`dimensions: 384`** (`EMBEDDING_DIMENSIONS`), 15s timeout. The result is
  length-checked (`=== 384`, else fallback). If `OPENAI_API_KEY` is missing/invalid,
  a deterministic **384-dim hash fallback** is used; an outer error fallback returns
  a 384-zero vector. **All paths produce 384 dims**, matching the
  `document_chunks.embedding VECTOR(384)` column and the `match_documents(vector(384))`
  RPC. (Was a 1536-vs-384 mismatch before 2026-06-01.)
- **How RAG works (current):** **RAG is disabled** — `chat/route.ts` gates it behind
  `RAG_ENABLED=false`, so no embedding is computed and `match_documents` is not
  called; chat answers without document context. Intended flow when re-enabled:
  embed query → `match_documents` (vector(384)) over `document_chunks` → inject
  top-5 chunks (threshold 0.5). Prerequisites: deploy the RPC **and** populate
  `document_chunks` (see §9), then flip `RAG_ENABLED`.
- **System prompts:** chat uses "elite academic research assistant for
  QuickNotes"; the route additionally builds a per-request instruction prompt; the
  client builds detailed per-format prompts (Key Points, MCQs, etc.).

## 9. UPLOAD SYSTEM

Source: [upload/route.ts](../app/api/upload/route.ts) +
[notes/generate/route.ts](../app/api/notes/generate/route.ts).

- **Accepted file types (MIME + extension):** PDF, DOCX, PPTX/PPT (placeholder
  text only — no real extraction), TXT. Old `.doc` returns a placeholder note.
- **Limits:** max **10 files**/upload, **50 MB**/file.
- **Extraction libraries + fallback chain (PDF):**
  1. `pdfjs-dist` (tries main import → `legacy/build/pdf.mjs` → `require()` of

## 10. STREAMING IMPLEMENTATION

Server: [aiService.ts](../app/lib/ai/aiService.ts) +
[chat/route.ts](../app/api/chat/route.ts). Client: [chat/page.tsx](../app/chat/page.tsx).

- **SSE format (exact):**
  - Content token: `data: {"content":"<text>"}\n\n`
  - Final metadata (server): `data: {"conversationId":"<id>","sources":[...]}\n\n`
  - Done sentinel: `data: [DONE]\n\n`
  - Error: `data: {"error":"<safe message>"}\n\n`
  - Heartbeat (server keep-alive): `: heartbeat\n\n` every 15s (SSE comment).
- **Frontend parser:** `fetch` → `response.body.getReader()`; `TextDecoder` with
  `{ stream: true }`; a `lineBuffer` accumulates partial lines across chunk
  boundaries, splits on `\n`, retains the last incomplete line; lines starting
  with `data: ` are JSON-parsed. Handles `content`, `error`, `sources`, and
  `conversationId` events; ignores `[DONE]`.
- **Buffer limit:** server `TransformStream` aborts if accumulated response
  exceeds **10 MB** (`MAX_RESPONSE_SIZE_MB`). Request body capped at **1 MB**;
  pdf markdown capped at **500 KB**.
- **Done sentinel:** `data: [DONE]` (emitted by both the gateway normalizer and
  the route flush).
- **Error format:** `{"error": "<message>"}` inside an SSE `data:` line;
  user-facing text is sanitized (`AiService.getSafeUserMessage` server-side and
  `sanitizeAIError` client-side).
- **AbortController:** **Yes.** The client holds `abortControllerRef`; "stop",
  "new chat", and component cleanup call `.abort()`. The server listens on
  `request.signal` `abort` to clear the heartbeat and release the in-flight lock.

## 11. AUTH SYSTEM

Source: [requireAuth.ts](../app/lib/auth/requireAuth.ts),
[supabase.ts](../app/lib/supabase.ts), and the SQL RLS policies.

- **Provider:** Supabase Auth.
- **Methods:** Email/Password and Google OAuth (`GOOGLE_CLIENT_ID` /
  `GOOGLE_CLIENT_SECRET`).
- **`requireAuth(request)` behavior:** Strategy 1 — if `Authorization: Bearer
  <token>` is present, create a Supabase client with that token and call
  `auth.getUser()`. Strategy 2 — fall back to cookie session via
  `createServerClient`. Throws `AppError(401, 'UNAUTHORIZED')` if no user.
  Returns `{ user, supabase }`.
- **Browser client:** `getSupabaseClient()` is a singleton (storageKey
  `quicknotes-auth-token`) to avoid Web-Locks token-refresh contention.
  `clearSupabaseClient()` + `clearSupabaseStorage()` run on sign-out to prevent
  cross-user state leakage.
- **Rate limiting (layers):**
  1. Edge `middleware.ts`: Upstash sliding window **10/min** on
     `/api/chat|upload|notes`, keyed by `x-user-id` | `sb-access-token` cookie | IP.
  2. In-route `globalRateLimit`: Upstash sliding window **15/min** per user id.
  3. `chat/history`: Upstash **60/min** per client IP.
  4. Per-user in-flight locks (Redis `SET NX EX`) for `chat`, `upload`, `notes`.
  **As of 2026-06-01, layers 1, 2, and 4 fall back to a per-instance in-memory
  limiter when Upstash is unreachable** (NOT fail-open): `middleware.ts` 10/min,
  `globalRateLimit` 15/min, `acquireInflight` per-instance lock. The fallback is
  per-isolate (not global) but still blocks an abuser hammering one instance.
  Layer 3 (`chat/history`) still soft-degrades (cache miss → DB). A separate
  legacy in-memory limiter ([rateLimiter.ts](../app/lib/rateLimiter.ts)) remains
  unused by active routes.
- **RLS status:** **Enabled on all 9 tables** with `auth.uid() = user_id`
  (feedback INSERT policy is open `WITH CHECK (true)`; feedback SELECT allows
  owner, anonymous-null rows, or an `is_admin` JWT claim). ⚠️ `chat/save`,
  `chat/export`, and `notes/generate` use the **service-role key, which bypasses
  RLS**; they enforce ownership manually in code.

## 14. ERROR HANDLING

Source: [errorHandler.ts](../app/lib/errors/errorHandler.ts).

- **`AppError(message, statusCode=500, code?, details?)`** is the typed app error.
- **`ErrorHandler.handle(error, context)`** returns
  `NextResponse.json({ success:false, message, error:{ code } }, { status })`.
  If the error is an `AppError`, its `statusCode`/`message`/`code` are used;
  otherwise the message/code string is matched against `ERROR_MAP`.
- **Code → user message mapping (`ERROR_MAP`):**
  | Match key | User message | HTTP status |
  |-----------|--------------|-------------|
  | `429` | "The AI is busy right now. Please retry in a few seconds." | 429 |
  | `RATE_LIMIT` | "You are sending requests too quickly. Please wait before trying again." | 429 |
  | `TIMEOUT` / `ABORT_ERROR` | "That took too long. Try a shorter question or document." | 500 |
  | `401` / `UNAUTHORIZED` | "Your session has expired. Please log in again." | 401 |
  | `DB_ERROR` | "Service is under heavy load. Please try again in a moment." | 500 |
  | `500` / `ECONNREFUSED` | "Service is temporarily unavailable. Please try again." | 500 |
  | (no match) | "An unexpected error occurred. Please try again." | 500 |
- **AI-specific safe messages:** `AiService.getSafeUserMessage` maps
  abort/timeout, 429, 401/403, and 5xx to friendly text before they reach the SSE
  stream. The client further sanitizes via `sanitizeAIError`.
- **Logging format:** `ErrorHandler.log` emits a single structured JSON line via
  `console.error` (`{ timestamp, context, name, message, code, stack?, details }`);
  stack traces only in development or when `DEBUG_MODE=true`. `ErrorHandler.debug`
  logs JSON only when `DEBUG_MODE=true`.

### Minting a test JWT
Browser: log in → DevTools → Application → Local Storage → `quicknotes-auth-token`
→ copy `access_token`. Bulk: `node tests/load/seed-users.mjs` (tokens expire ~1h —
re-run before a session; never commit `tokens.json`).

### Load pass/fail thresholds
Measure `POST /api/chat` (`deepseek/deepseek-chat` via OpenRouter, `MAX_TOKENS=2000`).
Start with `tests/load/chat-smoke.js` (10 VUs — the minimum bar: 0 5xx, 0 timeouts,
p95 < 30s). Then establish a single-user baseline `b` (p95 full-response) and judge
the ramp relative to it:

| Concurrency | Target full-response p95 | Non-429 errors | 5xx | Fail if |
|-------------|--------------------------|----------------|-----|---------|
| 10  | ≤ 1.25 × b | < 1% | < 0.5% | any 5xx > 0.5%, or timeouts > 0 |
| 25  | ≤ 1.5 × b  | < 1% | < 0.5% | 5xx > 1%, or p95 > 2 × b |
| 50  | ≤ 2 × b    | < 2% | < 1%   | 5xx > 2%, or sustained timeouts |
| 100 | ≤ 3 × b    | < 5% | < 1%   | 5xx > 2%, p95 > 4 × b, or timeouts > 1% |

**429 = PASS**, not failure — it proves the limiter works. Excess load must degrade
to 429, never 5xx or a hung stream.

> ⚠️ **Rate-limit caveat:** from one machine all k6 VUs share one source IP, and
> the edge limiter (`middleware.ts`) keys by IP → ~10 req/min total regardless of
> VU count. To measure true handler concurrency, in the **test env only** relax the
> `Ratelimit.slidingWindow(...)` values in `middleware.ts` + `app/lib/rateLimiter.redis.ts`
> or send a unique per-VU `x-user-id` header. Keep production limits intact. Full
> detail in `tests/load/README.md`.

### Category D — Design / responsive / UX (`tests/responsive/responsive.spec.ts`)
Viewports 375×667, 768×1024, 1440×900 against `/`, `/login`, `/chat` (mocked auth).
HARD assertion: no VISIBLE element overflows the viewport (>5px) — scanned via
`getBoundingClientRect()`, NOT `document.scrollWidth`, because `body{overflow-x:hidden}`
in `globals.css` masks the scrollbar. SOFT audit (non-failing annotations): every
interactive tap target <44px, every visible font <12px, and overflowers. Plus a
long-message + long-streamed-response layout test at 375px.

### Category G — Security input validation (`tests/security/input-validation.spec.ts`)
Body >1 MB → 413, question >50k chars → 400, malformed JSON → graceful (no 5xx hang),
markdown >500 KB → 413. All run before any LLM call (no AI cost). The rest of the
security review is static (see §18).
